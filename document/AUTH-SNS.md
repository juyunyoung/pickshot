# 로그인·SNS 연동 설계

- 작성일: 2026-10-25
- 관련: [PRD](./PRD.md) F-01, F-02, F-16 / 스키마 `supabase/migrations/20261025120000_auth_profiles_social.sql`

## 1. 구성 한눈에 보기

| 구분 | 방식 | 처리 |
|---|---|---|
| 로그인 | 구글 · 애플 · 카카오 · 페이스북(메타) | Supabase Auth 소셜 로그인 |
| 로그인 | 이메일 가입 (SNS 없이) | Supabase Auth 이메일+비밀번호 |
| 게시물 올리기 | 인스타그램 · 페이스북 · 쓰레드 | 로그인 후 '마이 > SNS 연결'에서 따로 연결 (메타 API) |
| 공유 (모든 앱) | 휴대폰 공유 시트 | 연결·심사 없이 바로 가능 |

- **로그인 연결과 게시물 연결은 별개.** 인스타그램·쓰레드는 Supabase 로그인 방식으로 지원되지 않아 로그인에는 못 쓰고, 게시 권한만 따로 받는다.
- iOS 앱에 소셜 로그인이 있으면 **애플 로그인 필수** (애플 심사 규정).

## 2. 로그인 기본정보 비교

각 서비스의 **기본 동의 범위**만 기준으로 함 (성별·생일·전화번호 같은 추가 항목은 받지 않음 — 개인정보 최소 수집).

| 정보 | 구글 | 애플 | 카카오 | 페이스북 |
|---|---|---|---|---|
| 서비스 회원 ID | ✅ | ✅ | ✅ | ✅ |
| 이메일 | ✅ | ✅ (가리기 선택 시 중계 주소) | △ 사용자가 동의 거부 가능, 비즈 앱 전환 필요 | △ 계정에 없을 수 있음 |
| 이메일 인증 여부 | ✅ | ✅ | ✅ | – |
| 이름 / 표시 이름 | ✅ 이름 | △ 첫 로그인 때만, 사용자가 수정·생략 가능 | ✅ 닉네임 | ✅ 이름 |
| 성·이름 분리 | ✅ | △ 첫 로그인 때만 | – | ✅ |
| 프로필 사진 | ✅ | – | ✅ | ✅ |
| 언어(로케일) | △ | – | – | – |

### 합집합 → 사용자 테이블 `profiles`
| 컬럼 | 내용 | 채워지는 경우 |
|---|---|---|
| `id` | 회원 ID (`auth.users` 연결) | 항상 |
| `signup_provider` | 가입 방식: email / google / apple / kakao / facebook | 항상 |
| `display_name` | 표시 이름 (구글·페이스북 이름, 카카오 닉네임, 애플 이름, 이메일 가입 입력값) | 항상 (없으면 이메일 앞부분, 애플 중계 주소면 '회원' → 앱 첫 화면에서 이름 입력받기) |
| `email` | 이메일 | 받은 경우 |
| `email_verified` | 이메일 인증 여부 | 항상 (기본 false) |
| `is_private_email` | 애플 '이메일 가리기' 중계 주소 여부 | 애플 |
| `full_name` | 전체 이름 | 구글·애플·페이스북 |
| `given_name` / `family_name` | 이름 / 성 | 구글·애플·페이스북 |
| `avatar_url` | 프로필 사진 | 구글·카카오·페이스북 |
| `locale` | 언어 | 구글 |
| `terms_agreed_at` / `privacy_agreed_at` / `marketing_agreed_at` | 약관·개인정보·마케팅 동의 시각 | 가입 후 동의 화면 [제안] |

- 서비스별 회원 ID는 Supabase가 `auth.identities`에 따로 보관 (한 사람이 여러 방식으로 로그인 연결 가능). `profiles`에 중복 저장하지 않음.

### 교집합 → 이메일 가입 입력 항목
구글·애플·카카오 모두에서 받을 수 있는 정보 = **이메일 + 이름(표시 이름)**

| 입력 | 필수 | 저장 위치 |
|---|---|---|
| 이메일 | ✅ | `auth.users` → `profiles.email` |
| 비밀번호 | ✅ | `auth.users` (Supabase가 암호화 보관) |
| 이름(닉네임) | ✅ | `profiles.display_name` |
| 약관 동의 · 개인정보 수집 동의 · 만 14세 이상 확인 | ✅ | `profiles.*_agreed_at` [제안] |
| 마케팅 수신 동의 | 선택 | `profiles.marketing_agreed_at` [제안] |

> 프로필 사진은 교집합이 아니라(애플 없음) 가입 때 받지 않고, 가입 후 마이 화면에서 바꿀 수 있게 함.

## 3. SNS 게시물 올리기

### 플랫폼별 조건 (메타 정책)
| 플랫폼 | 올릴 수 있는 곳 | 조건 |
|---|---|---|
| 인스타그램 | 사용자의 **프로페셔널 계정**(비즈니스·크리에이터) 피드 | 개인 계정은 API로 게시 불가 (앱에서 무료 전환 가능) / 메타 앱 심사 필요 |
| 페이스북 | 사용자가 관리하는 **페이지** | 개인 타임라인 게시는 API로 불가 / 메타 앱 심사 필요 |
| 쓰레드 | 사용자 본인 프로필 | 개인 계정 가능 / 메타 앱 심사 필요 |

- 공통: 메타가 이미지를 가져갈 수 있도록 **잠깐만 열리는 서명 URL**로 사진을 넘긴다 (버킷은 계속 비공개).
- 접근 토큰은 서버만 읽을 수 있는 별도 테이블에 보관, 만료 전 갱신.
- **[제안] 단계 나누기**: 1차 출시는 휴대폰 공유 시트(모든 앱, 심사 불필요) → 메타 앱 심사 통과 후 직접 게시 기능 오픈.

### 흐름
1. 마이 > SNS 연결 > 플랫폼 선택 → 메타 로그인 창에서 권한 동의
2. 서버가 토큰을 받아 `social_connections` + `social_connection_tokens`에 저장
3. 사진·프레임 촬영·만화 일기 화면에서 [SNS에 올리기] → 계정·문구 선택
4. `social_posts`에 등록 → 서버가 게시 → 결과(게시물 링크·실패 사유) 기록

### 테이블
| 테이블 | 용도 | 앱에서 접근 |
|---|---|---|
| `social_connections` | 연결된 SNS 계정 (플랫폼, 계정 ID, 게시 대상 ID, 사용자명, 상태) | 본인 것 조회·삭제 |
| `social_connection_tokens` | 접근 토큰·만료 시각 | **불가** (서버 전용) |
| `social_posts` | 게시 요청·결과 기록 | 본인 것 조회·요청 등록 |

## 4. 필요한 키·설정

| 항목 | 넣는 곳 |
|---|---|
| 구글·애플·카카오·페이스북 로그인 키 | Supabase 대시보드 > Authentication > Providers |
| 메타 게시용 앱 ID·시크릿 (페이스북·인스타그램·쓰레드) | `app/.env.local` 서버 값 → [ENV-SETUP.md](./ENV-SETUP.md) |

## 5. 준비할 것 (사용자)
- 카카오 디벨로퍼스: 앱 생성 + **비즈 앱 전환**(이메일 받으려면 필요)
- 애플 개발자 계정: Sign in with Apple 설정
- 구글 클라우드: OAuth 클라이언트
- 메타 개발자: 앱 1개에 페이스북 로그인·인스타그램·쓰레드 추가, 게시 권한 앱 심사 신청 (개인정보처리방침 URL 필요)
