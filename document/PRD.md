## 1. 개요

### 1.1 앱 이름 [확정]
- **픽샷 (PickShot)** — "내 픽(Pick)과 찍은 샷"
- '팹샷'보다 발음이 또렷하고, '원픽' 같은 표현과 자연스럽게 이어짐
- 이름이 핵심 기능과 바로 연결됨: **Pick** = 최애(친구 집·친구), **Shot** = 프레임 촬영·합성 사진

### 1.2 한 줄 정의
**내 최애와 함께 사는 집** — 최애 작품(집)과 캐릭터(친구)를 모으고, 캐릭터 프레임으로 같이 사진을 찍고, 하루를 AI 4컷 만화 일기로 남기는 앱.

### 1.3 기본 정보

## 2. 배경 및 목적

### 2.1 왜 만드나
1. **달조아랩 포트폴리오 확장** — 현재 실제 사례는 여행 앱 하나뿐. **AI 이미지 기능이 중심인 두 번째 사례**가 필요함.
2. **덕질 앱 시장 데모·영업 자산** — 홈페이지·크몽에 "덕질 앱도 만들어요"를 추가할 때 실제로 동작하는 앱을 보여줌.
3. **흩어진 두 앱을 하나로** — `cartoonDiary`(AI 만화 일기)와 `cartoonhouse`(만화 일기 + 친구 집 + 사진 합성)의 좋은 기능만 모아, 검증된 앱 구조(app + admin + supabase)로 **새로 만든다**. 기존 코드는 복사하지 않고 흐름만 참고.

### 2.2 보여주고 싶은 것 (세일즈 포인트)
| # | 포인트 | 앱 기능 |
|---|---|---|
| 1 | 사진 기능 + AI | 최애 사진으로 나만의 프레임(AI 배경 지우기) → 프레임 씌워 바로 촬영 |
| 2 | 생성형 AI | 하루 일기를 내 캐릭터가 나오는 4컷 만화로 자동 생성 |
| 3 | 꾸준히 쓰게 만드는 구조 | 작품(집)·캐릭터(친구) 수집, 호감도·앨범으로 쌓이는 재미 |

### 2.3 목표
- **사업 목표**: 완성 후 화면 캡처 → daljoalab.com 제작 사례(`#case`) + 크몽 포트폴리오 등록
- **제품 목표**: 스토어에 실제 출시 가능한 품질 (보안·저작권·비용 관리 포함)

## 5. 기능 상세

### 5.1 회원가입·로그인 (F-01, F-02)
- Supabase Auth만 사용. 로그인 방식(이메일 / 구글 / 애플 / 카카오) **[미정]**
  - iOS에 소셜 로그인을 넣으면 '애플로 로그인'도 함께 필요
- 가입 직후 `profiles` 생성

### 5.2 친구 집·친구 (F-03, F-04)
- **친구 집** = 최애 작품. 제목, 대표 이미지, 메모
- **친구** = 캐릭터. 이름, 메모, 대표 사진, 호감도
- 호감도: 사진 추가·촬영·합성 등 활동으로 올라감, 친구 순위로 표시 (올라가는 규칙 **[제안]**: 사진 1장 +1, 프레임 촬영 +3, 합성 +2)
- 캐릭터 이미지는 **사용자가 직접 올린 것만**

### 5.3 캐릭터 앨범 (F-05)
- 캐릭터별 사진 모음. 출처 표시: 업로드 / AI 합성 / 프레임 촬영
- 비공개 Storage + 서명 URL로만 표시

### 5.4 프레임 만들기 (F-06) — 신규 핵심
1. 앨범 사진 선택
2. AI 배경 지우기(누끼)
3. 틀 선택: 1컷 · 네컷 · 폴라로이드 · 스티커형
4. 캐릭터 위치·크기·회전 조절, 배경색·문구·날짜 넣기
5. (선택) "벚꽃, 파스텔"처럼 입력하면 AI 배경 생성
6. 저장 → `frames`

### 5.5 프레임 촬영 (F-07) — 신규 핵심
1. 프레임 선택
2. 카메라 화면에 프레임을 겹쳐 미리보기
3. 촬영 (네컷은 4회 연속)
4. 한 장으로 합성해 저장 → 해당 캐릭터 앨범에 자동 등록
5. 기기 저장 · 외부 공유

### 5.6 AI 합성 사진 (F-08)
- 입력: 내 사진 + 캐릭터 사진 + 키워드 2개
- 결과는 앨범에 저장
- **AI 안전 필터 기본값 유지** (기존 앱처럼 끄지 않음)

### 5.7 내 아바타 (F-09)
- 성별·나이·헤어·안경·주근깨 선택 → AI 얼굴 생성
- 프롬프트·seed 저장 → 만화 일기의 주인공 외형 고정에 사용

### 5.8 AI 4컷 만화 일기 (F-10)
- 입력: 일기 글, 무드, 스타일
  - 스타일 4종: cute / comedy / drama / minimal
  - 무드 10종: crying, curious, emotionless, motivated, normal, sad, sigh, soft_smile, surprised, very_happy — **무드를 프롬프트에 반영**
- 처리 흐름:
  `일기 → 기억 반영 → 스토리보드(컷별 장면·감정·대사·카메라) → 컷별 이미지 프롬프트 → 컷 이미지 생성 → AI 시각 검수(PASS/FAIL + 수정 힌트) → 실패 컷만 수정 후 재생성(최대 2회) → 완성`
- **반드시 4컷** (기존 앱의 1컷 하드코딩 문제 해결)
- 캐릭터 일관성: 첫 컷은 아바타 이미지 참조, 이후 컷은 앞 컷 참조 + 고정 seed + 짧은 외형 설명을 모든 컷에 추가
- 프롬프트 원칙: 영어, 카메라 앵글 다양화, 말풍선·글자 금지, 주인공은 "the character"
- 진행률을 실시간으로 보여주고, 앱을 껐다 켜도 결과 유지 (7.3 참고)

### 5.9 일기 검색·기억 추출 (F-11, F-12)
- 일기 임베딩을 pgvector에 저장해 뜻으로 검색
- 일기에서 인물·반려동물·장소·물건과 외형 특징을 뽑아 `memories`/`memory_facts`에 저장 → 다음 만화에 반영

### 5.10 관리자 웹 (F-13)
- 회원 관리, 신고 처리, AI 사용량, 프레임 템플릿 관리, 앱 업데이트 배포
- 역할(admin/partner/curator) + 메뉴 권한 테이블

## 6. 화면 구성 [제안]

### 6.1 하단 탭
| 탭 | 내용 |
|---|---|
| 홈 (친구 집) | 내 최애 작품 목록, 친구 순위 |
| 찍기 | 프레임 선택 → 촬영 / 프레임 만들기 |
| 일기 | 만화 일기 목록·작성·검색 |
| 앨범 | 전체·캐릭터별 사진 |
| 마이 | 프로필, 아바타, 설정, 남은 AI 사용 횟수 |

### 6.2 주요 화면
- 로그인 / 가입
- 친구 집 상세 → 친구(캐릭터) 상세 → 캐릭터 앨범
- 프레임 만들기 (편집기), 프레임 촬영 (카메라)
- AI 합성 만들기
- 일기 쓰기 → 생성 진행 → 4컷 만화 보기
- 아바타 만들기

### 6.3 핵심 흐름
1. 가입 → 첫 친구 집·친구 등록 → 캐릭터 사진 올리기
2. 사진으로 프레임 만들기 → 프레임으로 네컷 촬영 → 앨범 저장·공유
3. 아바타 만들기 → 일기 쓰기 → 4컷 만화 받기

## 7. 기술 구성 [확정 — 기존 앱 구조를 따름]

### 7.1 구성
| 영역 | 기술 |
|---|---|
| 앱 (`app/`) | TanStack Start(SPA 모드) + React 19 + Vite + Tailwind v4 + shadcn/Radix + React Query, Capacitor 8로 안드로이드·iOS |
| 관리자 웹 (`admin/`) | Next.js 15 |
| 백엔드 (`supabase/`) | Supabase (Postgres + Auth + Storage + Realtime + Edge Functions), pgvector |
| AI | Gemini **[확정]** (새 API 키 발급) |
| 키 관리 | 각 폴더 `.env.local` (커밋 안 됨) → [ENV-SETUP.md](./ENV-SETUP.md) **[확정]** |
| 배포 | Cloud Build → Cloud Run(Docker), 네이티브는 `cap sync` |

- 앱 코드 규칙: 파일 기반 라우트(`src/routes`, 하단 탭 `_tabs.*.tsx`), Supabase 쿼리는 `src/services/*.service.ts`, AI 호출은 `createServerFn` (비밀 키는 핸들러 안에서만 읽기)
- OTA: `scripts/publish-ota.ts` + `app_releases` 테이블 + `src/lib/ota/*`

### 7.2 데이터 (주요 테이블)
| 테이블 | 용도 |
|---|---|
| `profiles` | 사용자 프로필·아바타 정보 |
| `houses` | 친구 집 (최애 작품) |
| `characters` | 친구 (캐릭터), 호감도 |
| `character_photos` | 캐릭터 앨범 사진 (출처 구분) |
| `frames` / `frame_templates` | 사용자 프레임 / 관리자 제공 틀 |
| `diaries` / `diary_panels` | 일기 / 만화 컷 |
| `diary_embeddings` | 일기 검색용 벡터 (pgvector) |
| `memories` / `memory_facts` | 기억 추출 결과 |
| `jobs` | AI 작업 상태·진행률 |
| `ai_usage` | 사용자별 AI 사용 횟수 |
| `app_releases` | OTA 업데이트 |
| `admin_menu_permissions` | 관리자 메뉴 권한 |

- **모든 테이블 `auth.uid()` 기준 RLS** (전체 공개 정책 금지)
- Storage **비공개** 버킷: `avatars`, `characters`, `frames`, `photos`, `diaries` → 서명 URL로만 접근

### 7.3 AI 작업 처리
1. 앱이 `jobs` 테이블에 작업 등록
2. Edge Function(또는 서버 함수)이 백그라운드로 처리하며 `jobs.status/progress` 갱신
3. 앱은 Supabase Realtime으로 진행률 표시
→ 서버가 재시작돼도 작업 기록이 남고, 서버를 여러 대로 늘려도 문제없음

## 8. 비기능 요구사항

### 8.1 보안
- `.env` 등 비밀 값은 **절대 커밋하지 않음** (`.gitignore` 반영 완료)
- service role key는 서버 환경변수로만, 채팅·코드에 남기지 않음
- 인증 없는 API 없음. 남의 데이터 읽기·쓰기 불가 (RLS로 보장)

### 8.2 저작권·초상권
- 캐릭터 이미지는 사용자가 직접 올린 것만 사용
- 앱이 공식 이미지를 제공하거나 AI로 유명 캐릭터를 그리지 않음
- 사진은 기본 비공개
- 신고 기능 + 관리자 처리 [제안]

### 8.3 AI 비용 관리
- 사용자별 일일 횟수 제한 (예: 만화 일기 3회, 합성 10회) → `ai_usage`
- 남은 횟수를 마이 탭에 표시 [제안]

### 8.4 결제
- 유료 프레임 판매 시 **인앱결제**(애플·구글)
- 예약·실물 상품만 PG(토스페이먼츠) 사용 가능
